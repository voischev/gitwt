# Работа с gitwt

## Назначение и границы

- Универсальное ядро и CLI для Git worktree. Не добавлять управление сессиями,
  терминалами и координацию агентов. Адаптер OpenCode живёт в `opencode-gitwt`.
- `src/index.js` — публичный API; `src/worktree.js` — Git-операции;
  `src/config.js` — конфиг; `src/environment.js` — хуки; `src/process.js` — процессы.
- `bin/gitwt.js` — вывод CLI. По умолчанию текст для человека;
  `--json`/`--porcelain` — один JSON-ответ с `ok`, `command`, `data` либо `error`.
- `--skill` печатает переносимую инструкцию на английском. Работает вне Git,
  не меняет файлы и не устанавливает ничего в клиент; с `--json` возвращает `data.prompt`.
- Неизвестные статусы — `null`. Ошибки — stderr и ненулевой exit code.
  Вывод хуков не должен загрязнять машинный stdout.
- Реестр worktree принадлежит Git. Сохраняются только снимки хуков.
  Ошибка создания не повод автоматически удалять каталог; dirty-worktree
  защищён, а ошибка preRemove блокирует удаление даже с force.

## Изменения и зависимости

- Сначала читайте реализацию и окружающий код. Делайте минимальную правку.
- JavaScript ESM, Node.js >=22.14. Предпочитайте стандартные модули Node.js.
  Runtime-зависимостей нет; Biome нужен для разработки. Конфиги `.gitwt.json`
  и `~/.config/gitwt/config.json` читаются встроенным `JSON.parse`.
  Новую зависимость добавляйте только с конкретным обоснованием.
- README и минимальный CLI help — на английском; остальные сообщения CLI и тесты — на русском.
  Комментарии добавляйте только для неочевидных причин.
- Git запускается массивом аргументов. Shell допустим для явно заданных
  пользователем строковых хуков.

## Проверка

```sh
npm ci --ignore-scripts
npm run check
npm test
npm run release -- --check
```

Тесты используют временные Git-репозитории. Не используйте рабочие репозитории
пользователя как фикстуры. Покрывайте изменённое поведение, а не устройство кода.
Для правок только документации достаточно линта и проверки упаковки.

## Git и выпуск

- GitHub — основной репозиторий, SourceCraft — зеркало. Изменения через ветку и PR.
  Не переписывать историю, не пушить изменения прямо в main.
- Не трогать чужие незакоммиченные правки. Commit/push/merge и релизы только
  по просьбе пользователя. После merge удалять локальную ветку через `git branch -d`.
- Пакет `@voischev/gitwt`, команда `gitwt`. Версия в package.json и lock-файле
  должна совпадать с тегом `vX.Y.Z` на влитом коммите.
- GitHub Actions выполняет checks → mirror → publish. Зеркало обновляется
  без force; npm публикуется только из GitHub. Не передвигать выпущенные теги.
- `NPM_TOKEN` и `SOURCECRAFT_TOKEN` хранятся в GitHub Secrets; не печатать значения.
- В конце коммитов и внешних сообщений добавлять один блок:

```text
---
Co-Authored-By: LLM
Model: <имя модели без префикса провайдера>
```
